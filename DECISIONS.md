# Architectural decisions

## D1 — Custom Canvas 2D scene engine instead of Fabric.js/Konva
All visuals are a `Scene` of typed layers (`image`, `text`, `emoji`, `shape`, `country`, `search`, `dialogue`) rendered by one pure renderer (`src/engines/rendering/renderScene.ts`). The same renderer drives the editor, thumbnails, template previews, the audience slide, PNG/PDF/PPTX export. Interaction (hit testing, rotated resize handles, snapping, guides) lives in `src/components/editors`. This keeps the stored document structured and editable (never screenshots), makes exports pixel-identical to the editor, and avoids a second object model that would need syncing with persisted data.

## D2 — Pure, testable image pipeline
Effects operate on a plain `Raster {width,height,data}` (`src/engines/image`). All 25 effects, vector masks (brush strokes and polygons, normalised coordinates), cutout and silhouette are pure functions, unit-tested in Node and executed in a Web Worker in the browser (`src/workers/imageWorker.ts`) with main-thread fallback. Processed results are cached by parameters; originals are never modified. Mask coordinates are relative to the image *as it enters that effect* (the studio shows that stage when painting), so masks stay correct even after crops/rotations earlier in the pipeline.

## D3 — Automatic background removal without ML
Local automatic cutout uses edge-connected flood fill with a colour tolerance (works well for subjects on plain/studio backgrounds) plus manual brush/polygon refinement and feathering. A local segmentation model was not bundled: the permissively licensed options are large downloads, and AGPL libraries were rejected. Manual masking is fully functional either way.

## D4 — Custom waveform/audio engine instead of WaveSurfer.js
Audio is decoded once to PCM (`decodeAudioData`, or a native WAV decoder that preserves the original sample rate exactly), then an ordered list of operations (`trim, delete, reverse, gain, fadeIn, fadeOut, speed, loop`, each optionally ranged) is applied to a copy. Reversal reverses each channel independently. A small canvas waveform renderer (peaks, ruler, selection, markers, playhead) gives full control over selection semantics tied to the operation model. Processing runs in a Web Worker (`src/workers/audioWorker.ts`) with a main-thread fallback. Export is 16-bit PCM WAV (validated by tests). MP3 export is intentionally not offered (no encoder bundled). "Split" places markers that divide the clip into regions; clicking a region selects it for processing.

## D5 — Data model
- Zod schemas are the source of truth (`src/types/schema.ts`); game content is a discriminated union over all 13 modes. `scene` is the spec's `editorDocument`.
- Dexie tables: `questions`, `summaries` (lightweight rows for list views/search), `assets` + `assetBlobs` + `assetThumbs` (blobs separated so lists never load media), `thumbnails`, `templates`, `collections`, `quizzes`, `rounds`, `quizQuestionRefs`, `revisions`, `settings`. Versioned schema with an upgrade migration (v2).
- Media is content-addressed (SHA-256, unique index) and referenced by id; questions keep a `mediaReferences` multi-entry index so the app can warn before deleting referenced media. Deleting questions never deletes shared media.
- Optimistic concurrency: every save checks `version`; a mismatch raises a conflict dialog instead of silently overwriting.
- Undo/redo is an in-memory snapshot history with coalescing of rapid drags/slider moves; persistent revisions are separate (checkpoint every 5 minutes or on manual save, last 50 kept).

## D6 — Presentation privacy model
The host computes a `PublicState` (`src/features/presentation/model.ts`) containing only revealed information, plus a slide image rendered with the current reveal step. Only that is posted on the `BroadcastChannel`; question objects, answers, aliases, notes and unrevealed hints never leave the host window before reveal (unit-tested and verified end-to-end by intercepting channel messages). Audience windows say hello on load and the host replies with the latest state, so refreshes reconnect; a heartbeat shows connection status on both sides. Question audio plays from the host window.

## D7 — UI kit
Components follow shadcn/ui conventions (Tailwind v4 + Radix primitives + Lucide) but are hand-written in `src/components/ui` rather than generated by the shadcn CLI, to keep the dependency surface small. Theme tokens are CSS variables (dark charcoal default, light theme). TanStack Query is not used: Dexie `liveQuery` already provides reactive, cached async data.

## D8 — Geography scope
250 countries/territories from `world-countries`, with flags for all. 236 have their own Natural Earth 1:50m outline (Kosovo matched by name); 14 small territories without separate geometry (e.g. Gibraltar, Tuvalu, Réunion) are flagged in the UI and excluded from outline/neighbour pickers. Status badges distinguish sovereign, dependent and disputed (Kosovo, Western Sahara, Taiwan, Palestine) entries. Neighbours = land borders only. Countries without land borders show their region with nearby countries explicitly labelled "(nearby)", never as neighbours. Maps re-centre on the country's longitude to avoid antimeridian splits; "near"/"mainland" island filters remove distant overseas parts.

## D9 — Offline
`vite-plugin-pwa` precaches the app shell, the geometry and emoji data chunks and all flag SVGs, so authoring, presenting and exporting work offline after the first visit.

## D10 — AI
Provider abstraction (`src/features/ai-assistant/ai.ts`) with Ollama, an OpenAI-compatible local server, and Claude through a local Node proxy (`server/ai-proxy.mjs`) that uses the official Anthropic SDK so the API key never reaches the browser. Suggestions open in a review dialog where each item can be edited, selected or rejected; nothing is saved until accepted. The prompt forbids inventing quotations, and the Famous Dialogue mode deliberately has no AI generation.

## D11 — Exports
PDF via pdf-lib (rendered slides + text; standard fonts cannot encode emoji, which are replaced with `?` in PDF *text* only — rendered slide images keep them). PPTX via PptxGenJS using full-resolution rendered slides for layout fidelity, answer slides, speaker-note answers and embedded WAV audio. Progressive reveals, timers and live effects are not interactive in PowerPoint.

## D12 — Scoring and leaderboard
Scores are an append-only list of awards (`correct`, `wrong`, `bonus`, `adjust`) per team and question (`src/features/presentation/scoring.ts`), so marking is idempotent and undoable and totals are always derivable. They are stored per quiz in the settings table, so a host reload keeps the scores. The audience receives only names, colours, scores and ranks; ties use competition ranking (1, 1, 3) and the podium announces shared first place rather than picking a winner alphabetically.

## D13 — Generated content
The round generator and demo quiz only use validated country data (names, official names, alternative spellings, regions, capitals, land neighbours) and original text written for this app; no third-party media is bundled. Difficulty is a documented heuristic (land area, plus neighbour count for neighbour maps), not a measured statistic. A seeded PRNG makes rounds reproducible.

## D14 — Answer checking
`matchAnswer` normalises case, accents, punctuation and leading articles, accepts listed alternatives exactly, and reports small typos as "close" (≤1 edit for 4–7 characters, ≤2 for 8+, ≤3 for 16+; short answers must match exactly). The host makes the final call — the app never auto-awards points.

## D15 — Deferred answer reveal
The quiz setting `answerReveal` (`each` | `round` | `quiz`, optional for backward compatibility; default `each`) changes only how slides are sequenced: question slides carry a phase (`ask` / `review`) and an `answerable` flag. In deferred modes the ask slides are never answerable, and `buildPublicState` checks this itself, so a stray host state (shortcut, jump, reload) still cannot send the answer to the audience. Review slides show the whole question (all reveal steps, no timer) and reveal the answer on Space. Scoring is keyed by question id, so teams can be marked during the run-through.
